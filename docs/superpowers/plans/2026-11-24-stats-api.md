# Chronos Stats API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only FastAPI service over `chronos-stats.db`, plus a derive step at the end of every snapshot run, serving all V1 features in `STATS_PLAN.md`.

**Architecture:** `bot/snapshot.py` (existing, runs every 15 min via systemd) calls a new `bot/derive.py` after writing history. Derive computes activity, totals, firsts, milestones, badges, rivalries and name lookups. `api/` is a FastAPI app on `127.0.0.1:8765`, proxied by nginx at `/api/stats/`. It opens SQLite read-only and caches every response keyed by `data_version`. Participant rules live in exactly one module, `api/scope.py`, which derive imports.

**Tech Stack:** Python 3.14 on server (3.13 locally is fine), sqlite3, FastAPI, uvicorn, orjson, nbt (existing), pytest + httpx (dev only).

**Spec:** `docs/superpowers/specs/2026-11-24-stats-api-design.md` (read it alongside this plan; `STATS_PLAN.md` and `CLAUDE.md` hold the scope rules).

## Global Constraints

- Every "value at T" query reads the latest row with `at <= T`. Never sum history rows in a range.
- `from` earlier than `tracking_started_at` is clamped to it, and the response carries `effective_from`.
- SMP bot rule: not in a team = bot, no exceptions. **Missing `player_flags` row on smp = bot.** `include_bots` (default `false`) affects only `server_key='smp'` rows.
- CMPs never filter bots. Scope groups come from `servers.group_key`, never hardcoded.
- `participant_kind='unresolved'` scoreboard rows never appear in any result.
- `scoreboard_meta.is_vanilla_mirror=1` objectives never appear in scoreboard listings or search.
- No hardcoded stat/objective lists in API or derive. The only literals allowed are the activity key `minecraft:custom`/`minecraft:play_time` and the seed rows for `milestone_rules`.
- Derive failure never fails the snapshot. It's recorded as `snapshot_runs.kind='derive'`, `ok=0`.
- API connections are `mode=ro` + `PRAGMA query_only=1`.
- Mojang calls: `POST https://api.minecraftservices.com/minecraft/profile/lookup/bulk/byname` (≤10 names/request) and `GET https://sessionserver.mojang.com/session/minecraft/profile/<uuid-no-dashes>`. At most 60 HTTP calls per derive run in total. Failed and not-found lookups are cached and not retried for 7 days.
- Range presets: `1d`=86400, `1w`=604800, `1m`=2592000, `6m`=15724800, `1y`=31536000 seconds, `all` = from tracking start.
- Series are downsampled to ≤500 points, keeping step shape (last value per bucket).
- Response headers: `ETag: "<data_version>-<sha1(path?query)[:12]>"`, `Cache-Control: public, max-age=60, stale-while-revalidate=900`.

## Review Focus

1. **A name that maps to several uuids** (a renamed account, an old cache entry): `/player/{name}` must return the uuid with the latest `players.last_observed`, not 500 or an arbitrary one. → test in Task 9.
2. **A player whose first history row is after `from`**, i.e. joined mid-range: the delta counts from 0, not from "missing". They must not be dropped from range leaderboards. → test in Task 7.
3. **Empty scope or a key not present** (e.g. `scope=building`, `kind=scoreboard`; building has no objectives): 200 with an empty list, never 404/500. → test in Task 7.
4. **Running derive twice on the same run** (a crash and retry, or a manual run): no duplicate milestones, firsts or badges, and seeding never happens a second time. → test in Task 5.
5. **Mojang API down or rate-limited (HTTP 429/5xx/timeout)**: derive still completes and the snapshot is unaffected, with the lookup retried after 7 days rather than every run. → test in Task 3.

### Task 4: Derive (activity, last_activity, meta, totals) + hook into snapshot

**Interfaces:**
- Consumes: `api.scope.is_counted`, `MojangClient`
- Produces:
  - `derive.run_derive(conn, run_at: int, mojang: MojangClient | None) -> None`, which runs each stage in order: `derive_activity`, `derive_totals`, `derive_firsts`, `derive_milestones`, `derive_rivalries`, `derive_badges`, `derive_spotlight`, `resolve_names`, `write_meta`. Each stage is `fn(conn, run_at) -> None` (resolve_names also takes mojang).
  - meta keys: `data_version` (= `MAX(snapshot_runs.id)`), `tracking_started_at:<server_key>` (= `MIN(at)` of stats runs with `ok=1 AND entries_read > 0`; **the live DB has early ok=1 runs with entries_read=0 that must not count**), `last_run_at`.
- snapshot hook: after the server loop, `sys.path.insert(0, str(REPO_ROOT))`, then `run_derive` inside try/except, then `record_run(conn, "all", "derive", ok, err, None, None, ms)`. `snapshot_runs.server_key` REFERENCES `servers(key)`, so `sync_servers_table` must also upsert a pseudo row `key='all', label='All', group_key='all', provisioned=0` (provisioned=0 keeps it out of `resolve_scope`).

Stage definitions:
- `derive_activity`: for rows in `stat_snapshots WHERE at=run_at AND category='minecraft:custom' AND stat_key='minecraft:play_time'`, INSERT OR IGNORE `activity`; then `players.last_activity = MAX(activity.at)` for those uuids. **Skip on the very first run** (no prior stats run with `entries_read > 0` for that server). Every player is "changed" on the first run, and that isn't activity.
- `derive_totals`: for each (server, category, stat_key) touched at `run_at`, recompute `SUM(value)` and the bot-filtered sum from `stat_current`. If they differ from `stat_totals_current`, insert a `stat_totals` row and upsert current. Same for scoreboards (players only, non-mirror).

### Task 5: Derive firsts, milestones, badges, rivalries, name resolver

**Files:** Modify `bot/derive.py`. Create `tests/test_derive_achievements.py`.

**Interfaces:**
- Consumes: Task 4 stage signatures; `api.scope.is_counted`.
- Milestone rule seeds (inserted with `INSERT OR IGNORE` on every derive):
  - category-wide (`stat_key` NULL), thresholds `[1000,10000,100000,1000000,10000000]`: `minecraft:mined`, `minecraft:used`, `minecraft:crafted`, `minecraft:broken`, `minecraft:picked_up`, `minecraft:dropped`, `minecraft:killed`, `minecraft:killed_by`. rule_key = `cat:<category>`.
  - `minecraft:custom`/`minecraft:play_time`: hours `[100,500,1000,5000,10000]` × 72000 ticks.
  - `minecraft:custom`/`minecraft:walk_one_cm`: km `[100,1000,10000]` × 100000.
  - `minecraft:custom`/`minecraft:deaths`: `[100,1000,10000]`.
  - Scoreboards get no default milestone rules (units unknown). The rules table supports adding them later.
- Seeding marker: meta key `seeded_achievements=1`. Seeding happens on the first derive where the marker is absent, and then never again.

Stage definitions:
- `derive_firsts`: seed: for every (server, category, stat_key) in `stat_current` (and every non-mirror objective in `scoreboard_current`, category `'scoreboard'`) with no `firsts` row, insert the top counted holder (`value > 0`, ties broken by uuid) with `earliest_known=1`, `at=run_at`. After seeding: for keys with no firsts row that have changed rows at `run_at`, insert the counted player with the highest value among this run's rows, with `earliest_known=0`. Use `INSERT OR IGNORE` on the unique index.
- `derive_milestones`: seed: every counted current value ≥ threshold gets a row with `earliest_known=1`. After seeding: for each changed row at `run_at`, take the previous value (latest row `at < run_at`, else 0) and insert each threshold with `prev < threshold <= new`, `earliest_known=0`. Use `INSERT OR IGNORE`.
- `derive_badges`: implements **spec Addendum A1 exactly** (9 families, 36 keys; badge_keys as listed there). Per server, counted players only, insert-if-new, never deleted, `server_key` always set. Night Owl's "server-local time" uses `time.localtime` on the server (CET). Overtaker is awarded inside `derive_rivalries` (below).
- `derive_rivalries`: implements **spec Addendum A2**. Module constants `RIVALRY_MIN_VALUE = 1000`, `RIVALRY_MAX_GAP_RATIO = 0.02` (tuned on live data; see spec A2), `RIVALRY_PER_PLAYER = 5`, `RIVALRY_PER_KEY = 3`. Order: (1) award `overtaker` for stored pairs whose B now ≥ A; (2) delete all rows; (3) recompute adjacent pairs with all A2 filters, where "active" = an `activity` row in `[run_at-7d, run_at]` and "moving" = `gap != gap_7d_ago` and B's 7-day delta ≥ 1; (4) apply the per-key cap, then the per-player cap.
- `derive_spotlight`: implements **spec Addendum A3**. It rebuilds `spotlight_candidates` with the 5 triggers (`outlier`, `rare`, `recent_milestone`, `recent_first`, `mover`) and their exact thresholds. Runs after `derive_badges`.
- `resolve_names(conn, run_at, mojang)`: up to the client's remaining budget, `uuid_to_name` for players with `name_resolved=0` ordered by `last_observed DESC`, then upsert with `name_resolved=1`.

  - `@dataclass class Range: from_ts: int; to_ts: int; effective_from: int; is_now: bool`
  - `parse_range(conn, scope: Scope, range: str|None, from_: int|None, to: int|None, now: int) -> Range`. Raises ValueError on a bad preset or from > to. Clamps to the min `tracking_started_at` over the scope's servers.
  - `stat_values_at(conn, scope, include_bots, category, key, ts: int|None) -> dict[str, int]`: per-uuid value **summed across the scope's servers**. `ts=None` reads `stat_current`; otherwise `SELECT uuid, value, MAX(at) … AND at<=? GROUP BY server_key, uuid`, then summed in Python per uuid.
  - `scoreboard_values_at(conn, scope, include_bots, objective, ts|None) -> dict[str,int]` (same shape)
  - `downsample(points: list[tuple[int,int]], from_ts, to_ts, max_points=500) -> list[tuple[int,int]]`: step-preserving. The first point is always `(from_ts, value_at_from)`.
- `GET /api/stats/leaderboard?kind=stat|scoreboard&category=&key=&scope=all&range=|from=&to=&include_bots=false&limit=50&offset=0`. For `kind=scoreboard` the objective name goes in `key` and `category` is ignored. Returns `{"effective_from","to","mode":"total"|"delta","total_count","rows":[{"rank","uuid","name","value"}]}`. `mode` is `total` when no range/from is given (current values), else `delta` = values_at(to) − values_at(effective_from). Missing at from = 0. Rows with delta 0 are dropped. Ties share a rank (competition ranking 1,1,3). `limit` is capped at 200.
